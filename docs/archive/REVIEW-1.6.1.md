# v1.6.1 代码与文档复核

日期：2026-09-07；基线：v1.6.0 / 98511cc。

## 修复

| 级别 | 问题与触发条件 | 修复 |
| --- | --- | --- |
| P1 | 应用目录没有外部脚本时，ScriptLocator 会选中当前工作目录内同名 PowerShell 脚本；从不可信目录启动并打开实验/朋友测试可能选中非发行脚本 | 只允许两种已知脚本名；仅使用应用目录或重新提取的嵌入资源，移除工作目录回退 |
| P1 | 系统工具及 PowerShell 使用裸文件名启动，依赖可被启动环境影响的搜索路径；以管理员运行时会放大错误程序被执行的影响 | Windows 工具和 PowerShell 固定系统目录；nvidia-smi 仅使用系统目录或 NVIDIA 的 Program Files/NVSMI 目录；未知工具拒绝执行 |
| P2 | 配置导入在检查 Ids 之前覆盖同名方案，损坏 JSON 可被保存后才报错，且原保存接口吞掉写入错误 | 保存前验证名称、非空列表和 catalog ID；覆盖需确认；保存失败明确报告 |
| P2 | NativeSystem 顺序读完 stdout 再读 stderr，子进程大量错误输出时有管道互等风险 | 同时读取两个流，再等待退出 |
| P2 | 安装器编译器探测将查找失败等同未安装，难以区分用户目录、PATH 和沙箱执行权限问题 | 显式路径/环境变量、PATH 与默认目录查找；CheckOnly 实际启动诊断，兼容 Windows PowerShell 5.1 |
| P2 | 测试版本断言写死 1.5.0，v1.6.0 的“162 全通过”不能复现 | 从 Directory.Build.props 获取预期版本 |

以上执行路径问题属于本地文件/环境信任边界风险，本次未发现或声称存在可远程无条件利用的漏洞。应用安装目录、运行账户及其可写数据目录仍需由用户保护；本补丁不提供对已控制本机账户的攻击者的隔离。
