# 设置易用性与实时指标修复

## 根因与修复

- GPU 原实现每 21 轮完整重建计数器，并主动丢弃重建轮的值。改为按实例名增量更新，仅新增实例需要基线；保留存活实例，释放消失实例。刷新失败时仍尝试读取原有有效计数器。
- Dedicated Usage 是当前显存用量，不需要像利用率一样丢弃首次读数。
- CPU 的连续 48 轮基线没有缺失，但每次切换概览 / 检测均会重新创建采样器并预热。两页现共享应用级采样器，页面隐藏只取消订阅，窗口隐藏暂停、退出释放。
- CPU 计数器异常时释放并重建，避免持续使用故障句柄。真实失败仍显示缺失，不复用旧数值冒充当前值。
- 低配选项即时调整共享采样间隔。

## 设置界面

- 分为外观与显示、启动与通知、游戏与方案、数据与维护四个入口，每类独立滚动，保留原有操作。
- 主题提供三块大预览，实心青色表示选中，同时有勾选标记和键盘焦点边框。
- 外观页新增界面模式选择；与顶栏按钮双向同步。顶栏按钮也改为实心青色。

## 验证

- Release 编译成功；185 项测试通过。
- 新增三项计数器生命周期回归测试：增量刷新不丢基线、构建失败回滚并释放新句柄、原始值首轮可用且真实失败不填旧值。
- 同一台机器、同样 48 轮采样，排除第 0 轮预热：修复前 CPU 0 / GPU 2 / 显存 2 次缺失；修复后均 0 次。此结果证明已复现的周期性空值修复，不代表所有驱动永远可用。
- 实际窗口核对深色与浅色布局、设置分类切换、切到检测页直接获得已有采样。
- 对照原始记录在本地 review-output/metrics-probe/before.tsv 和 after-verified.tsv；after.tsv 使用了 dotnet run 旧输出，已识别并排除，不作为修复证据。
- 只读验证，没有应用真实系统优化，也没有修改安装版或 Release 资产。

参考：[Microsoft PerformanceCounter.NextValue](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.performancecounter.nextvalue)：需要两次读数的计数器首轮仅建立基线，重建计数器会重置该状态。
