# FPS 帧律 · 开发计划与产品路线图

> 更新：2026-09-02（v1.4.1 发布）。本文是产品方向与开发节奏的唯一权威说明，
> 与 catalog.json 的"优化项唯一数据源"定位平行。

## 产品定位

一句话：**Windows 玩家的系统层帧率调校台**——检测、解释、执行、还原，
全流程可逆、数据可验证，不碰游戏本身。

五条产品红线（任何开发不得违背）：

1. **安全闭环**：所有系统改动写前备份原值（含"原本不存在"状态），可逐项/一键还原，已达标项跳过不写。
2. **零侵入**：不修改游戏文件、不注入进程、不读游戏内存、不与反作弊交互、不伪装硬件、不关引导虚拟化。
3. **数据说话**：每项优化的价值主张都应可被 A/B 实验验证；解释不清收益的项不进 catalog。
4. **全 FPS 通用**：优化项是"系统层"的，不绑定特定游戏；游戏相关的只做路径级适配。
5. **可信透明**：所有改动有 JSON 审计记录；默认无遥测。

## v1.5 —— 性能洞察与实验体验升级（已完成，v1.5.0，2026-09-02）

1. **可复用采样内核**：`MetricsSampler` 实例拥有生命周期（可释放、可测试），
   CPU/内存/GPU 利用率 + GPU 专用显存（GPU Adapter Memory 的 Dedicated Usage）；
   多引擎按 (luid, phys, engtype) 去重、多进程求和、多适配器取最大，避免重复累计；
   不可用时显示"不可用 + 原因"，不伪造 0；有界缓冲；低配模式 3 秒采样 + 更小窗口。
2. **性能会话与洞察**：新页面支持开始/停止/命名/取消，实时四指标曲线与摘要
   （样本数/均值/峰值/P5/P95），会话持久化（schemaVersion=1、原子写、损坏留档、
   保留 30 个、中断恢复），两次会话并排比较，JSON/CSV 本地导出；
   性能洞察卡片只做保守的启发式判断并标注"不代表因果"。
3. **A/B 实验室 2.0**：五步向导状态机（基线→三个候选组→报告）持久化到
   `experiment/wizard.json`，可从旧 `state.json` 迁移、中断后可解释可重试；
   每步可关联一次性能会话，报告合成脚本原始指标与会话摘要（`report-latest.md`）；
   `tuning-experiment.ps1` 参数、输出与 PS5.1 兼容保持不变，`-Simulate` 仍是安全验证入口。
4. **自动 Profile 活动中心**：启动边沿触发行为保持只读轮询不变；
   新增本地审计事件（匹配/应用/跳过/失败 + 原因，上限 200 条，不含完整路径），
   设置页可按结果筛选、清除，显示最后扫描时间与下一次触发条件。
5. **诊断导出 2.0**：zip 先在安全临时目录组装再原子移动；新增 `概览.md` 与机器可读
   `report.json`；覆盖版本与源码标识、硬件与显存可用性、最近会话摘要、A/B 状态、
   自动 Profile 事件、备份健康与设置摘要；用户名/用户目录/盘符路径统一脱敏；
   默认不上传任何数据。

## v1.1 —— 功能补全（已完成，v1.1.0 ~ v1.2.0）

1. **优化项分类分组**：catalog 增加 `group` 字段（键盘/鼠标/显示/网络/系统/电源/启动），
   优化页按分组渲染小节头，搜索框旁加分类过滤 chips。
2. **配置方案 Profiles**：把自定义勾选保存为命名方案（本地 JSON），
   支持导出/导入分享；为 v1.2 的"按游戏自动应用"打地基。
3. **托盘常驻**（v1.2.0）：最小化到托盘、全局热键呼出、优化完成通知（复用 PiWeb Desk 的成熟经验）。
4. **A/B 实验增强**（v1.2.0）：历史报告可视化（均值/1% low 折线对比，history.jsonl 只追加）。
   实验步骤向导化仍留待后续打磨。
5. **细节打磨**：检测页体检项可展开解释；首页快捷入口记住上次访问页。

## v1.2 —— 体验纵深（中期）

1. **应用内自动更新**：Release API 检查 → 下载 → SHA256 校验 → 静默执行安装器升级。
   未签名安装包仍可能触发 SmartScreen，代码签名证书是后续发布质量项。
2. **硬件监控面板**：检测页实时小图表（CPU/内存/GPU 占用，及可用时的 GPU 显存占用）。
   不读取温度：温度需要内核驱动，超出本项目只读、无驱动边界。
3. **按游戏自动应用**：检测到绑定游戏进程启动时，自动应用对应 Profile
   （后台常驻进程 + 计划任务实现，遵守红线 2）。
4. **诊断报告导出**：一键打包系统信息 + 优化状态 + 备份清单，
   用于远程帮朋友排查问题（朋友测试流程的线上化）。
5. **优化项扩充（走"五处同步"清单）候选**：
   显示器刷新率/色域体检、音频独占排查、存储写入缓存策略、
   DirectStorage 就绪检查、BCD 深度项评估。

## v2.x —— 方向探索（长期）

1. **优化项插件化**：允许第三方以包形式贡献优化项（catalog 扩展 + 沙箱审计 + 显式启用）。
2. **多语言**：en-US 起步，资源字典化。
3. **性能基线对照**：匿名聚合"同硬件的典型帧率分布"（与红线 5 冲突，仅显式 opt-in，默认关闭）。
4. **官网与文档站**：安装率统计同样遵循 opt-in 原则。

## 工程治理（贯穿所有版本）

- **版本**：Directory.Build.props 单源；每次发布 = 打 tag + Release（安装包+便携包+SHA256）。
- **质量门禁**：catalog 一致性测试必须绿；涉及引擎的改动跑真实 apply→restore 闭环；
  界面改动本地启动逐页人工验收。
- **四处同步清单**（新增优化项）：catalog → C# apply/revert case（NativeOptimizationEngine）
  → 状态读取（DetectionService）→ BackupService 建档；测试口径同步。
- **已知债务**：无 UI 自动化测试（低优先，人工验收足够）；
  `fps-tune.ps1` / `legacy/delta-gui.ps1` 已于 v1.4.0 删除（CLI 由 exe 无头模式承接）。

## 风险与依赖

| 风险 | 影响 | 对策 |
|---|---|---|
| GitHub 账号被风控标记（申诉中） | 检查更新/对外下载不可用 | 申诉解封；过渡期可用网盘镜像发布 |
| 安装包未签名 | SmartScreen 劝退率高 | 评估 OV/EV 代码签名证书（年费成本） |
| 反作弊误判（理论上不会） | 用户封号风险 | 红线 2 是产品设计约束，永不让步 |
| 单人维护 | 节奏波动 | catalog 架构已把"新增项"成本降到数据+两处实现 |
