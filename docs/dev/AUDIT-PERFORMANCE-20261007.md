## 冗余功能判断

1. **两套概览 + 独立优化页的重复入口**是主要界面冗余。控制台概览含完整优化列表，经典概览维护另一套呈现与事件链。本轮先修订阅和共享采样，保留用户已有模式；下一轮可收敛成一套概览，以“当前游戏→检测→验证”为主路径，优化选项留专页。删除模式属于产品选择，当前没有擅自移除。
2. **会话与 A/B 应保留各自职责**：前者是只读采样/历史/对比，后者是带系统改动的受控实验。可共用采样和帧时间统计，不应为减少页数混成一次不透明操作。
3. **联系/二维码、静态社区驱动版本建议**对游戏调优主流程价值较低，可收进关于/帮助。后者已经声明非官方且可能过期，后续宜改成官方驱动信息入口，不能用旧推荐证明有效。
4. **待核实体检项**（DirectStorage 的 Shader Model、音频独占）目前不具备完整自动诊断能力，应继续标注未知或收起到高级信息；不能展示为已确认，也无需为它们新增后台轮询。
5. **暂缓 HUD、后台自动应用和更多监控功能扩展**，先补完已有交互验证及隐藏时负载测试。HUD 如果后续做，应复用现有采样并按需开启。
