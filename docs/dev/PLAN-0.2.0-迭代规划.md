## M1 实测闭环：让每项优化「本机有数」（推荐旗舰）

**痛点**：36 项优化都有如实描述，但用户看不到"你这台机器上实测 Δ 多少"；A/B 实验室功能完整
（PresentMon、向导、历史）但门槛高——要手动建实验、懂采样；红线「解释不清收益不进 catalog」
也限制了扩展速度（P3-10 调研里多项因证据不足只能列为"评估为不做"或弱收益定位）。

**核心认识（v2）**：实验引擎是现成的且已覆盖"基线门控 → 自动应用（带备份）→ 采样 → 对比
报告 → 还原"全链路，缺的不是管线，是**三件事**——组可自定义、结论可沉淀、结论可露出。

**内容**：

1. **自定义实测组**（泛化 `Groups`）：优化页勾选的集合直接作为一组实验（整套实测主模式）；
   单项深测 = 勾 1 项（size-1 组）。基线稳定性门（CV>0.05 拒绝并提示"保持同一地图/画质/路线"）、
   自动应用 + 备份 + 报告 + 还原**全部复用现有实现**，不新造调度器。
2. **判定沉淀（新存储）**：实验结论（项集合 → ΔavgFps / Δp1Low / 样本数 / 采样条件 / 时间）
   持久化为 verdict 存储（LOCALAPPDATA 下独立 JSON，原子写）。
3. **两级实测徽标**：项级徽标（「本机实测 +x.x% 1% LOW」）来自含该项且已判定 keep/reason
   的实验；方案/概览级来自整套实测。有数才显示，没有不编。
4. **P2-2 报告导出**：实验报告一键导出中英短报告（测试条件 / 样本时长 / 样本数 / 对比指标）。

**明确修正**：实测报告与判定**不进会话历史**（会话无 FPS，见 §0-3）；"给会话加 PresentMon FPS"
列为 M1 可选子项单独拍板（会因此给"记录一局"引入 PresentMon 前置依赖，需用户点头）。

**红线约束（写死在验收里）**：需重启的项不进自定义实测组（UI 过滤，防无效实验）；样本不足或
噪声过大（基线不稳定）时引擎已拒绝继续——报告**「无法区分」**语义沿用，绝不硬凑数字。

**工作量**：**中**（v1 估"大"基于"新建管线"的错误前提；引擎复用后 = 泛化分组 + 判定存储 +
两级徽标 + 导出 + 测试）。

## M2 多游戏上下文：全 FPS 通用红线的深化

**现状**：`AppState.GamePath` 单值；`fso-off` / `gpu-pref` / `game-priority` 三项的 per-game
注册表键只服务一个游戏。`AutoProfileService` 已能按进程名自动切换**方案**（Profile），
但**检测上下文与游戏级优化项仍是单游戏**。

**内容**：多游戏档案——添加多个游戏 exe，每游戏独立的检测快照 / 优化状态 / 建议上下文；
游戏切换器（概览卡或侧栏）；与 AutoProfile 绑定打通（切游戏 = 切上下文，与既有"切进程 = 切方案"
互补而非重做）。

**红线约束（2026-09-29 复核补充）**：per-game 检测快照**另存**（如 `last-detect-< gameId >.json`），
**不得动 `last-detect.json` 与 CLI `-Detect -Json` 的键结构**（有测试逐字节依赖；CLI 语义维持
"当前机器/当前游戏"）；catalog **不引入 per-game 维度**（游戏维度放应用层状态，item 定义不变）；
旧单游戏数据迁移为默认游戏档案（套 `LegacyMigrations` 先例）。

**工作量**：大（AppState / 引擎 / 备份记录的 gamePath 键维度化 + UI + 迁移旧单游戏数据）。

## M3 实时监视 HUD + 自动记录

**内容**：桌面临悬浮小窗（FPS / 1% LOW / CPU / GPU，置顶、可点击穿透、可关）；检测到绑定游戏
进程启动 → 自动开始「记录一局」，退出自动保存。与 M1 共用采样管线，让实测数据零成本积累。

**零侵入**：ETW / PresentMon 外部采样（`MetricsSampler` 既有路线），不注入、不读内存、不碰反作弊。

**工作量**：中。

## M4 安全闭环升级：改动总览 + 一键全还原

**内容**：「本工具改过什么」审计页——所有被本工具改动过的注册表 / 电源 / 服务项的
当前值 vs 原值 diff 中心（数据已存在于逐项备份记录里，缺聚合视图）；一键全还原
（`RestoreAll` 已有基础）；可选的定期自动快照。
**约束（2026-09-29 复核补充）**：审计页**只读**，每行跳转既有逐项还原入口——不新造
第二条还原路径，还原仍全走 `BackupService`（含校验、管理员预检、`.restored` 审计）。

**工作量**：中（主要是聚合视图 UI）。

## 持续线（不占里程碑）

- **优化项扩展批次三**：依赖 M1——新项能用本机实测证明收益后，「解释不清收益不进 catalog」
  的预审就有据可依，扩展速度加快。
- **P2-7 国际化重启**：用户已两次确认暂缓。若 0.2.0 要面向英文用户推广可纳入，否则继续搁置。
- **工程债**：catalog schema 版本化——0.1.x 已多次加字段，M2 动多游戏时 catalog 结构必变，
  顺势加 `schemaVersion` + 旧数据迁移（`LegacyMigrations` 已有先例）。

## 明确不做（防跑偏）

- 不做 GPU/CPU 超频（风险等级不属于本工具；MSI Afterburner / 厂商工具已覆盖）。
- 不做"网络加速器"类功能（无可核实机制，红线「数据说话」）。
- 不做账号 / 云同步（单机工具，零收益高风险）。
- 不做游戏内注入式 Overlay（红线「零侵入」一票否决；M3 的 HUD 只做独立置顶窗口）。
